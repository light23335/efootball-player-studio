一、总体判断

冷血终结：可推进。真实射偏处理层已找到；还需接好对方禁区、最近对手距离和射门类型条件，并覆盖误差的各个分支。
手术刀直塞：可推进。方向偏差与前摇调速的基础入口都已找到；直塞的准确动作子类型白名单仍需核实。
从容不迫：可推进。可复用近距离检测、传球减偏和前摇调速；需要明确“传球偏差”是否包含方向之外的距离、力度和高度误差。
钢铁支点：设计成立，但暂不宜直接落码。“背身护球”需要真实护球状态与身体朝向；“稳定性 +20%”也需要先确定可度量的输出，不能直接套紧密控球或身体接触面板。

结论不是“给四个现成函数各乘一个倍率”。前三项需要把条件和已定位的效果层接起来；钢铁支点还缺护球对抗结算层的确认。

二、四项技能共用的规则

1. 距离

按球员在场上的地面位置计算 X/Z 平面距离，忽略跳跃的 Y 高度。冷血终结和从容不迫使用最近对方在场球员，不能用最近任意球员、盯人目标距离或球到防守者距离代替。
“防守球员”建议理解为正在防守一方的球员，不要求其注册位置是后卫，也不额外要求对方按下抢球或施压。
建议默认包含门将；若希望排除门将，应作为明确的范围调整，而不是代码中偷偷排除。
2 米和 1.5 米均包含边界。实现时可比较距离平方，分别对应 4 和 2.25 平方米；原生坐标与米的换算须先用比赛球场标尺校准。

2. 前摇

建议定义为“原生传球动作正式开始，到本次传球实际出球的触球事件之间”。按键蓄力时间、尚未接到球的等待、AI 决策等待不应混入这 20%。
前摇缩短 20%：T_new = T_original * 0.8。
相应播放速率：R_new = R_original / 0.8 = R_original * 1.25。
不能用速率乘 1.2 代替；乘 1.2 只对应时间缩短约 16.67%。
出球后恢复该动作原有速率 R_original，不能写死恢复成 1.0。动作取消、失败回退、换人、球权切换或切换动作时也需要清理状态。
两个 20% 快传加成若相乘，会得到 0.8 * 0.8 = 0.64，即前摇缩短 36%。本报告建议同一前摇效果取最强一档，默认不重复叠加。

3. 偏差

应缩放原生瞄准结果之后的随机偏差增量，而不是把世界角度、三维出球速度或失误类别评分直接乘倍率。
方向角存在 0/360 度回绕，应对最短有符号角度差缩放。例如原方向 359 度、实际方向 1 度，偏差是 +2 度。
降低偏差幅度不等于射正率、传球成功率或进球率提高同样百分比。原生辅助瞄准、目标选择和系统性的方向修正也需要与随机误差区分。

三、冷血终结

原需求
  射门；在禁区内射门且最近防守球员距离不超过 2 米时，射门偏差降低 15%。

建议的明确口径
  在对方禁区内出脚射门，且出球时距离最近对方球员不超过 2 米，射门的横向和纵向随机瞄准偏差幅度降低 15%。
  禁区位置建议以出球时射门者的地面位置为准，禁区线计入；这是建议的判定点，实施前需要固定下来。
  不增加当前重炮的蓄力 >=0.5 门槛，原需求没有这个限制。

效果定义
  方向随机偏差：delta_yaw_new = delta_yaw_original * 0.85。
  仰角随机偏差：delta_pitch_new = delta_pitch_original * 0.85。
  例：2 度的方向误差变为 1.7 度，1 度的仰角误差变为 0.85 度。
  建议把“射门偏差”明确为瞄准散布；球速和射门力量另算。若希望连球速随机误差也收敛，需要单独写进定义。

触发时机
  在本次射门实际生成出球误差时读取位置和最近对手距离。同一次射门只应用一次。
  应识别原生射门动作及子类型，不能根据射门按钮、动作名称或已进入击球通用函数就认定是射门。
  普通射门、特殊射门、凌空、头球、直接任意球和点球需要分项验证；报告未把尚未验证的子类型算作已经覆盖。

已确认的基础
  实际误差处理位于 0x6d52a04 及其下游；0x6d51d80、0x6d51bd8 可以实际写出方向、仰角和速度扰动。
  原生禁区边界数据已有具名接口 PenaltyAreaX / PenaltyAreaZ。
  球员位置和阵营读取路径已找到，可计算最近对方球员距离，无需依赖含义不明的“压力值”。

待完成
  对方禁区方向归一化与半场交换；坐标单位与边界字段语义校准。
  所有射门误差分支的覆盖，尤其不能只处理两个随机生成函数便认定完整。
  距离判定的动作快照及有效在场对象过滤。

评价
  这项与重炮有清楚的区分：冷血奖励禁区内受近距离防守的终结，重炮现有资格偏向蓄力和特定动作类别。

四、手术刀直塞

原需求
  传球；进行直塞时，传球方向偏差降低 20%，传球前摇缩短 20%。

建议的明确口径
  原生动作被确认为直塞后，本次直塞的水平随机方向偏差乘 0.8，动作开始到实际出球的时间乘 0.8。
  “方向偏差”在此按水平瞄准散布定义，不顺带把整个出球速度乘倍率。
  地面直塞、挑传直塞应分别列入动作白名单；不能因为挑传直塞属于空中球就把所有长传、传中一并加成。
  本报告未擅自把“直塞”限定为仅地面直塞；挑传直塞仍需确认相应原生子类型和完整误差处理。

效果定义
  delta_yaw_new = delta_yaw_original * 0.8。
  T_windup_new = T_windup_original * 0.8，即触球前速率 R * 1.25，出球后恢复 R。
  例：方向误差 2 度变为 1.6 度；前摇 30 帧、后摇 20 帧的理想示例变为约 24+20 帧。
  这不是整段动画变成 24+16 帧，也不是传球固定提速 20%。实际帧数受原生事件调度和离散帧影响。

实现顺序
  确认持有技能 -> 原生直塞动作正式启动 -> 保存动作序号和原速率 -> 加快触球前部分 -> 真实出球时收敛方向随机误差 -> 恢复原速率。
  如果动作选择失败并回退成普通传球，必须按最终选中的动作重新决定资格。

已确认的基础
  0x6ddbf6c -> 0x67902c0 支持对已有动作轨道中途调速，与重新启动动作的接口分开。
  0x6dbe318、0x6dd8740 -> 0x6dda6c4 提供击球事件时间与事件窗口处理的依据。
  实际击球误差层已定位；需要在该层按直塞类型筛选。

待完成
  直塞与挑传直塞的准确请求类型、最终动作类型及子类型编号。查到 THROUGH_PASS 字符串或原生“直塞球”技能名字，不足以认定新技能的正确动作判定入口。
  水平随机误差在全部直塞分支及后处理中的覆盖。
  事件时间换算、动作预测与实际播放速率的一致性。

评价
  前摇和方向散布是两项独立、清楚的增强，适合作为第一批实现，但应分别验收，避免“动画快了”掩盖减偏入口接错。

五、从容不迫

原需求
  在对方球员 1.5 米范围内进行短传时，传球动作前摇缩短 20%，传球偏差降低 20%。

触发条件
  持有技能，并正式启动符合白名单的短传；最近对方在场球员距离 <=1.5 米。
  最近的队友不能触发；不额外增加“对方正在抢球”的条件。
  建议普通短传、直塞、长传/传中分开分类，避免地面直塞因也属于地面传球而自动同时吃两项快传技能。最终以确认后的原生动作白名单为准。

必须补清的“偏差”口径
  手术刀明确写的是“方向偏差”，本项写的是更广的“传球偏差”，两者不能直接视为完全相同。
  方案 A：只收敛水平随机方向误差到 80%。实现范围较窄，技能文案应相应明确为“短传方向偏差降低 20%”。
  方案 B：收敛短传的方向、仰角和出球速度的随机扰动分量到 80%。这样更贴近宽泛的传球偏差，但要逐一确认原生分支，不能保证物理落点误差也恰好缩小 20%。
  本报告建议首版采用 A 并写清文案；如果保留原需求中较广的“传球偏差”，应按 B 补查和验收，不能只改方向便宣布完全实现。
  对速度扰动收敛的含义是“原本理想速度 100、随机误差 +/-6，变为 +/-4.8”，并非把传球速度固定增加 20%。

前摇与距离的取样时机
  为了加快前摇，必须在动作启动时就判定近距离条件，不能等球已经传出去再追溯缩短前摇。
  建议默认：以动作正式启动时的 1.5 米距离生成并锁定本次资格，两项效果都使用此资格；同一次动作中不因距离来回跨线而反复调速。
  这应明确写为“在对手距离不超过 1.5 米时开始短传”。
  若坚持出球瞬间也必须 <=1.5 米，则精度加成应在出球时复核；前摇已经发生的提速无法撤销。此时可能出现“启动时被贴防，后来对手离开，前摇已经缩短，但出球精度不加成”。两种语义都可设计，必须事先选定。

效果定义
  前摇时间乘 0.8；方向误差按方案 A 乘 0.8，或按方案 B 对确认的随机分量乘 0.8。
  不把地面传球面板值直接乘 1.2，也不把一次传球成功率直接增加 20 个百分点。

待完成
  短传准确白名单；1.5 米判定的动作快照；误差口径 A/B；出球及取消时的恢复。

评价
  这项的设计核心是“近距离被贴防时更快完成短传”，与手术刀的进攻传球用途不同。原需求没有指定的距离快照与误差范围，应在实现前写进规格。

六、钢铁支点

原需求
  背身护球且防守球员距离不超过 1.5 米时，控球稳定性提高 20%。

建议的触发结构
  持有技能 -> 自己确实控球 -> 进入原生护球/背身对抗状态 -> 同一个施压对手位于身后且距离 <=1.5 米 -> 才应用护球对抗增强。
  不能只检测“控球中”；不能只检测护球键被按下；不能将移动方向当成身体朝向。
  距离和身后角度必须针对同一个对手，避免“对手 A 很近、对手 B 在背后”错误拼成触发条件。
  优先使用实际护球对抗对象；若原生状态没有对象，再从范围内符合背后角度的对手中选取候选。

背身角度的可实现部分
  身体朝向和对手位置数据已有入口。可用身体正前方向与“自己指向对手”的地面向量点积判断对手是否位于身后。
  可供讨论的首版角度为身后左右各 60 度，即归一化点积 <=-0.5；这是本报告提出的设计值，不是从原 APK 读出的护球阈值。
  身后角度只是条件之一，仍需原生护球状态，防止背对对手带球跑、转身、倒地或离球时误触发。

“稳定性 +20%”需要选择指标
  A. 护球对抗抗性/判定裕量乘 1.2。
  B. 受接触造成的失稳或被挤开量乘 0.8。
  C. 受压丢球概率乘 0.8。
  这三种不是数学等价效果。单纯身体接触或紧密控球面板提高 20%，也不能代替其中任一项。
  本报告倾向 A，更符合“支点”定位；建议文案改为“背身护球对抗抗性提高 20%”。但原生护球对抗专用抗性/结算入口尚未确认，因此此处是推荐目标，不是已经找到一个可直接乘 1.2 的地址。

已确认与容易接错之处
  属性 25 是控球、26 是紧密控球、41 是身体接触、42 是身体控制；APK 映射中没有一个已经确认、直接叫“控球稳定性”的独立字段。
  原生具名 CheckBallKeep -> 0x81aff30 -> 0x7304568 / 0x730b0d0 检查持球有效状态；它没有直接检验身体朝向、对手距离或护球对抗结果，不能当成背身护球判定。
  原健步的紧密控球时间窗入口也不能移用成钢铁支点的稳定性入口。

待完成
  原生护球状态与实际对抗对象的识别。
  对抗结算中决定失稳、挤开或丢球的真实输入/输出及其有效范围。
  指标 A/B/C 的最终选择、退出状态恢复与身体碰撞后的反馈验证。

评价
  可以保留这个技能设计，但在上述问题确认前，不建议用“紧密控球 +20%”占位并宣称已经实现。它的补查工作明显多于前三项。

七、与现有技能及彼此之间的关系

1. 手术刀与从容不迫
   建议同一类方向减偏最多取 20%，同一前摇最多缩短 20%。两项分别识别原生动作，不因按键或“地面球”大类而扩大范围。
   如果以后明确允许重叠，也应在说明里写清是取最强还是相乘；不能无意得到 36%。

2. 冷血与重炮
   目前重炮修改的是失误类别评分，并不等价于实际角度散布乘 0.8，所以不能把现状直接算作 0.85*0.8。
   如果将来重炮也改为真实角度随机误差乘 0.8，则两者相乘得到 0.68，即散布幅度减少 32%；若不想这么强，可采取取最强一项。该规则尚未实施。

3. 手术刀与长传好手
   挑传直塞可能与长传类型重叠，应单列处理。
   现有长传好手使用一次性 1/0.88 倍率，尚没有只影响前摇的阶段控制；不能把这项整段倍率混算成已实现的“只缩短前摇”。
   设计上建议前摇类额外增益取最强，并保存、恢复其他原生或技能造成的基础速率；暂不修改现有长传好手。

4. 技能标记空间
   四项持有标记与每次动作的临时资格应分开。现有比赛标记 71 已被重炮用作临时资格，不能再拿来表示某项新技能的永久持有状态。
   新技能的编辑器展示、保存、球员编译、原生标记映射和运行时消费需要一起审计；本报告没有分配或占用新编号。

八、已核实的原生证据

以下均是该引擎的 ELF 虚拟地址；运行时需加库加载基址。

1. 减偏层
   0x6d52a04：击球误差处理的主要调用层。
   0x6d51d80 / 0x6d51bd8：可实际写出方向、仰角和速度扰动。
   0x6d547d4：后续条件性修正；本次进一步核对到 0x6d54a30 比较当前状态 9 后，才可能进入 0x6d54a94..0x6d54ac8 的额外随机方向修正。这是通用击球处理中的条件分支，不应一概称为所有射门都有的后处理。
   0x6d52ba4..0x6d52c70：失误类别分流；部分分支走其他处理，不能只包两个生成函数便宣布全覆盖。

2. 前摇分段基础
   0x6ddbf6c -> 0x67902c0：更新已有动画轨道的速率与倒数；前次局部原生执行验证过 1.25 -> 1.0 的速率切换。
   0x6dbe318：击球事件时间读取；0x6dd8740 -> 0x6dda6c4：事件附近的时间窗口判断。
   两个速率字段本身没有证据可直接命名为前摇/后摇开关，仍要用真实出球阶段控制恢复。

3. 位置、阵营和身体朝向
   0x6d3d9d4 返回 player+0x8 的位置对象。
   0x69baf90 通过动画组件位置接口 0x678f1ac 更新 player+0x8/+0xc/+0x10。
   0x6d3f934 返回 player+0x20 的身体朝向数据；0x69bb048..0x69bb068 从组件读取朝向、转为角度并写入，不能把 +0x20 当成上一帧位置。
   0x697d0f8：常规球员 ID 0..10 属于一方，11..21 属于另一方；本次执行原生函数验证了全部 22 个 ID。特殊对象与无效 ID 仍须过滤。
   0x72c4068 / 0x72c408c：球员对象访问路径；最近对手扫描仍需核对对象有效性和在场状态。

4. 禁区边界
   ELF 重定位的具名表把 PenaltyAreaX 映射到 0x72a767c，把 PenaltyAreaZ 映射到 0x72a76b4。
   两个 getter 从几何配置读取 +0x18 / +0x1c。本次用合成配置验证了真实读字段的位置；合成的 36、20 不是本 APK 球场尺寸实测值。
   原生 CheckNearPenaltyAreaLine（0x818bdd4）也使用这两个字段，但它检查的是禁区线附近，不等同“在对方禁区内”。
   原生代码按坐标与边界阈值比较，不能把 PenaltyAreaX 随意当成禁区深度，也不能只用绝对坐标而把双方禁区一起判入。

九、建议的实施与验收顺序

阶段 1：补全共用条件层
  核实位置单位、攻击侧、禁区边界与有效对手集合；确认射门、短传、地面直塞、挑传直塞的原生类型白名单。

阶段 2：建立误差与动作阶段控制
  明确误差的基准值和随机增量，覆盖分支与后处理；保持原生随机数采样，不为技能另抽一轮随机数。
  按球员和动作序号记录资格、原速率及恢复状态，只给真实执行的动作应用一次，避免在预测调用或每帧回调里重复乘倍率。
  同步核对动作预测、触球时间换算与实际播放速率。

阶段 3：实现冷血、手术刀、从容
  先用相同球员、相同原生随机输入做开关对照，再分别验证触发范围、减偏比例及前摇/后摇时间。

阶段 4：钢铁专门补查
  找到真正护球与对抗结算层，确定稳定性指标，再实现和验收。

需要覆盖的关键边界
  冷血：对方禁区内/线外、双方半场交换、距离 2 米及略大于 2 米、附近只有队友、门将近身、不同射门子类型。
  手术刀：地面/挑传直塞分别验证、普通短传和传中不误触发、动作回退/取消、不同原生基础速率、触球后恢复。
  从容：1.5 米及略大于 1.5 米、启动与出球间对手跨线、短传与直塞边界、两项技能同时存在。
  钢铁：正面/侧面/背后、护球与普通带球、背向移动但身体朝前、同一个施压对象满足角度和距离、球权和护球状态结束。
  减偏：对正负误差及角度跨 0/360 度分别核对；球本来没有随机误差时仍保持零误差。
  时间：前摇和后摇分别记录。前摇缩短约 20%，不能通过整段动画一起加快来冒充；不能把输入蓄力缩短误记成动作前摇缩短。
