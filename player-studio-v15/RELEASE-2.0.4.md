# 球员工坊 V17 2.0.4

本地修订：已将用户提供的液态玻璃新界面合入 2.0.4。保留本版全部后端修复、自动保存、动态保存按钮、肤色色块和 AI 卡池开关。PC 与 Android 同步公开发布，XI 分支不包含在本次发布。

新界面包括悬浮导航、球员卡展台、卡面取色、总览和手机布局。PC 与安卓启动图标统一采用新版蓝紫玻璃卡片 P 图标；安卓保留原签名和原生组件。原新界面输入目录保留。

- **内容增量 v2**：兼容原 V17、工坊派生、共存及已装 v1／v2 内容包的来源。仍核对 V17 原生接口、资料表布局与容器格式，不以包名、签名、数量、整包哈希或纯净基底表哈希作为拒绝条件。以当前 APK 为副本追加，保留已有 DIY 球员、教练、素材、设置和签名。所供 v2 含 192 张卡、10 条显式美术绑定和 114 条来源模板元数据，新增持久教练 0；工坊预设按完整图层签名去重。新增卡作为原版库内卡参加 AI 抽取，不计入个人 DIY。
- **逐项合并与冲突报告**：已有相同内容复用；同 ID 的用户修改保留。无法完整重写引用的资源冲突跳过受影响卡及其传递依赖，避免半张卡。展示新增、复用、更新、保留用户修改、跳过冲突数量，可保存报告；再次导入同一 ZIP 自动复用成功项并重试未完成项。报告另保存在 data/content-reports。技术失败不切换当前库。
- **美术加载修复**：原始安装器指纹与注册表准备后的指纹分开核对。原包绑定与全部内容绑定按球员 ID 合并，使用一次准备流程；导出预检从实际原生准备结构开始，启动使用相同的原始回退入口、分配器与工作器，不按内容包数量叠加安装器。仍保留指纹和结构校验。已经用旧程序生成过报错 APK 的，需要用新版工坊重新生成游戏 APK，再同签名覆盖。
- **球员回收站**：在“从已有球员复制”中逐张或勾选移入；“回收站”可恢复。工坊保留资料，下次生成从原生球员表、可用卡库、卡包和 AI 抽取排除具体卡 ID，原版与增量卡均适用，不按同名或整个球员身份扩大删除。按用户明确要求，游戏里已持有的同卡也会移除，并重映射阵容与定位球职责。首次处理前，在游戏 SQLite 存档旁生成 `studio-recycle-backups` 备份。恢复允许重新打包，不自动发还游戏中的已移除持有实例；完整旧存档仍在备份。共用贴图、模型保留，避免影响别的版本。
- **页面整理**：移除“更新与迁移”的快照、旧球员包迁移页面和 API。工程导入导出、APK 数据更新及本次内容增量导入保留。实装按钮改为“生成两份安装文件”。

- **肤色**：六档都能选择，改为“编号＋肤色说明”，增加可点选的六色色块。色块采自原包 `T_Sk1–6_Skin_D` 漫反射贴图中央区域的中位色，只是无光照参考，不代表游戏灯光下的最终颜色。脸部原贴图不会随档位重绘。
- **工坊队徽预览**：补齐 V17 `IDSPUCL27` 的替换资源和曼联等队徽的彩色命名分支，俱乐部优先于国家。缺少俱乐部图像时不再用国家图冒充；游戏端原本正常的队徽不改。
- **AI 卡池范围**：新增“AI 随机阵容包含已实装 DIY 球员”，默认开启。关闭后同时排除当前及以前安装的工坊 DIY 卡，保留原有排除名单、五星门槛和其余组队要求；玩家自己的 DIY 卡仍可正常使用。
- **旧设计大小图混用保护**：自建卡最终 F07 图层固定使用完整大图，小头像维持独立资源；F04 合成底图、F06 装饰和已烘焙日期按原有合成方式处理，绕开部分旧卡种的文件别名分支。遍历全部预设验证大图路由，并执行 ARM64 图层赋值测试；不改原版球员图。阿根廷、巴西等已有工程需要重新生成游戏 APK 后生效，实际画面仍需实机确认。
- **自动保存**：球员、教练、卡包、游戏设置及组别进度编辑自动保存。未填完整的教练、卡包以独立草稿保留，完善后更新正式条目。右上角按钮随当前编辑对象显示“保存球员／保存教练／保存卡包／保存设置”；自动保存不重建正在输入的表单。
- **抽卡演出回退**：抽卡响应和演出过滤恢复为 2.0.3 的实现及配置，移除本轮试验的 REVIVAL 恢复策略；其它游戏、资料和存档修复保留。自建球员不再放入未验证的多人物复演分支。这是精确回退，不宣称新增恢复了原版全部演出。
- **射门编码修正**：原生完整指令核对 0=普通、1=控制、2=挑射、3=紫射；4 保留为“原生模式 1”，不冒称已确认其界面含义。修复重炮攻门曾误写成 2 导致吊射的问题。
- **技能射门概率**：80% 概率应用技能射门偏好，20% 完整保留原生类型与力度。触发后，弧线落叶射门／掠地瞬击／重炮攻门仍按拥有的技能等权选择。选中重炮时，原生力量超过 50% 不动，不超过 50% 才补到 65%；只有禁区外才转紫射，禁区内保留原生类型。技能与动作的原生条件仍适用，不能保证每次一定播放技能动作。
- **内切与独狼**：仅在进攻三区的原生持球候选决策触发，80% 应用工坊策略，20% 保留原生选择。同一 30 原生 tick 决策窗口固定结果，不因多次调用而反复抽签。未选独狼时，机会接近的动作类别仍等权；独狼的优先选择规则保留。
- **盘带与动作日志**：修正 GameActor 与 PlayerInfo 对象表混用。记录双方原生状态、动作选择、持续移动采样、内切／独狼候选的原始及最终射门／传球／盘带类别、射门前后类型和力量、原生模式标记。原生未知动作只记编号，候选选择与移动采样不冒充最终动画或已确认控球。保留入口门槛计数、心跳、比赛分卷及 15 秒快照导出；日志在游戏私有目录 outputs/efootball/player-actions，并尝试复制到 Download/PlayerStudioLogs。
- **AI 精确排除名单**：新增排除 V18／V19 内置雅辛、巴洛特利、奥巴梅扬、卡卡、托马斯·穆勒、J罗、博阿兹·索洛萨的指定强卡；玩家仍可使用。同名其它卡和用户 DIY 不因姓名被排除。
- **AI 联赛**：D3 初始 1200，达到 1500 升 D2，达到 1800 升 D1，保留越线实际评分；D1–D3 阶段内不降级，分数下限为 1800／1500／1200。D10–D4 十场一轮，胜3平1负0；跳过只提前结算已经确定的结果。升级程序不会主动重置原进度。

下位组晋级值采用 D10=3、D9=13、D8=15、D7=16、D6=17、D5=18、D4=23。已检查所供 V17 包：其中没有完整的官方规则表；D10 有原始响应记录，D4 按用户指定，其余沿用该离线包表，保级采用原服务 4 分回退值。因此不能标为完整官方复刻。上位组评分增减采用锁定开赛对手强度的离线 Elo 近似公式，也不是官方精确公式。

最终回归：773 项 Python 回归检查（25 项因缺少相应外部输入跳过，其余通过），75 项 JavaScript 测试通过。原生测试执行完整射门处理器，核对挑射／紫射不同标志；盘带候选日志与观察前后决策一致，覆盖对象分表、力度边界、禁区、概率分布及原生保留路径。当前修订尚未做新的游戏实机验收，整场动作覆盖仍待安装验证。
