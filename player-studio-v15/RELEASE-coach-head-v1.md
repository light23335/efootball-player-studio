# 教练三维头模测试版

基于 1.9.15.5，支持复制教练的独立三维头模与原版资源替换。未构建 Android 编辑器安装包。

2026-10-28 黑脸修复：自制教练头模现在按每个 LOD 的 `LODMaterialMap` 更新实际使用的材质。上一版只更新材质槽 0，而手机默认 LOD1 会跳转到槽 3，导致新模型 UV 读取原版贴图，出现黑脸、白眼。现在 HQ/MQ 均绑定私有图集，保持原有骨架与 LOD 设置。已用用户保存的斯洛特 GLB 生成 APK，独立解码确认两档贴图像素均与导入文件一致；游戏内显示仍需安装后确认。

新增自建教练删除：教练管理页可勾选“只看自建教练”，在教练卡片点击“删除教练”并确认。删除前自动备份，同时移除本机已保存球员工程中的对应教练副本与预览选择。原版教练、已导出的 APK 和游戏内教练不在删除范围内。

## 复制教练并导入自己的新脸（推荐）

1. 在“教练管理”勾选“只看有三维头模的教练”。选择原版教练，点击“复制为自建”。
2. 编辑页新增“这名自建教练的独立三维头模”，会自动读取该原版教练的模型作为骨架模板。
3. 可先“导出原版 GLB 模板”，保持原坐标和骨架编辑，再“导入我的 GLB 脸模”。兼容的骨骼和表情权重保留；不兼容的骨架采用头颈中性绑定并明确提示。
4. 点击页面底部“保存并用于预览”。每名自建教练保存自己的 GLB 和原版骨架来源。
5. 到“APK 实装”勾选这名自建教练，生成并安装游戏 APK。无需在原版头模工作区额外保存替换。
6. 在游戏中选择这名自建教练，在原本会出现教练的入场、庆祝或其他镜头验收显示和动画。

现有永久教练 ID 保持不变。模型按该 ID 生成独立的 `DemoFace/Manager/SK_编号_Face` 路径；同一模板可以复制多份，每份使用自己的模型和私有材质。原版模板与其他复制教练不会被覆盖。

复制无三维头模的原版教练仍可编辑姓名和能力，但不会凭空获得动画模板。不同骨架 GLB 不能自动获得原版眨眼、张嘴等表情；推荐基于导出的原版骨架编辑。

## 替换原版共享资源（另一种用途）

1. 打开“教练管理”→“打开头模工作区”。资源准备完成后列出实际存在的 `DemoFace/Manager/SK_*_Face.uasset`。
2. 搜索姓名或资源编号，选择目标，查看带贴图的三维模型。支持旋转、缩放、平移、线框和骨架显示。
3. “导出当前预览 GLB”可导出游戏坐标中的完整模型。推荐以原版 GLB 为起点，保持米制、骨架和原坐标，编辑后导入内嵌贴图的 GLB。
4. 可以选择另一个原版教练头模，或导入自制 GLB。软件先验证并显示替换结果；保存后才列入 APK 导出。
5. 在“APK 实装”勾选“写入已保存的教练头模替换”。允许不选择任何球员，仅写入头模。

## 范围

- 替换现有模型路径，使用该路径的所有教练都会受影响。列表中的姓名是编号匹配结果，不能替代比赛内实际加载验收。
- 自建教练独立头模走编辑页的新入口。教练姓名、能力和二维头像保留原有功能。
- 原版换头保留供体模型及其材质依赖。自制模型使用目标教练的骨架、偏移与原生 LOD，生成私有材质和贴图，避免覆盖公共材质。
- 导出时同步替换主 APK 内原始容器中的教练模型副本，避免仅追加到球员补丁包后被原始模型遮盖；其余容器资源保持原内容。
- 自制模型多材质合并为贴图图集，使用原生遮罩材质处理头发与睫毛；着色和比赛表情仍需游戏内检查。
- 兼容骨架保留可用权重；不兼容的骨架采用原生头骨中性绑定，并提示表情权重未迁移。原导入文件保留。
- 原版共享替换配置保存在 `data/coach-heads.json`，不随球员工程分享。自建教练的独立头模保存在教练 JSON 的 `head_model` 中，并随引用它的球员工程携带；GLB 文件位于 `data/assets`。备份时请保留整个 data。
- “取消已保存的替换”影响下一次构建。已导出的 APK 不会被修改；恢复原版时，应使用未含本次替换的来源 APK 重新生成。

- 浏览器测试覆盖预览、GLB 下载、两种替换、保存、重新打开、APK 导出选择与窄窗口布局。
- 已执行仅含教练头模替换的真实 APK 构建，签名和资源读回校验通过。未安装游戏验收。
- 已构建包含两名同模板自建教练的真实 APK，分别使用两份不同形状的 GLB。独立 CUE4Parse 解码确认两份模型、私有材质均可读取，原版模板字节与主容器保持原样。
- 实际执行 V17 ARM64 教练文件名加载函数 `0x3a84b08`，以有界字符串、分配与资源存在性桩验证新教练 ID 能解析到其自身的模型路径。缺失模型时返回空，模型存在时返回该新 ID 对应的键。不修改引擎代码。
- 比赛中的实际镜头、动画与着色仍需安装游戏验收；桌面解码和指令模拟不等于游戏内测试。

## 重新构建 Windows EXE

使用 Python 3.12 x64。安装 `requirements-build.txt`，运行 `prepare_source.py`，补齐 tools 和 Three.js build 资源，再运行：

```powershell
python build_windows.py --dist-dir "E:\实况足球\球员工坊-V17-教练头模测试版"
```

核心新增文件：`coach_heads.py`、`web/coach-heads.js`、`tests/test_coach_heads.py`。入口修改位于 `app.py`、`web/coach-ui.js`、`web/native-package-ui.js`，APK 集成位于 `native_package.py`。

独立复制教练扩展：`coach_models.py`、`web/coach-model.js`、`resources/native-coach-model-loader.json`、`tests/test_coach_models.py`。兼容原版骨架/绑定姿态检查与独立路径的原生加载验证一并保留。
